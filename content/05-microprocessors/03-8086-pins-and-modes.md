## Signal groups

| Group | Pins | Purpose |
|---|---|---|
| Address/data | AD15–AD0 | low 16 address bits during T1, then 16 data bits |
| Address/status | A19/S6 – A16/S3 | high 4 address bits, then status information |
| Bus high enable | BHE̅/S7 | 0 → the high data byte (D15–D8) is used |
| Read / write | RD̅, WR̅ | memory or I/O read / write strobe |
| Memory or I/O | M/IO̅ | 1 → memory cycle, 0 → I/O cycle (`IN`/`OUT`) |
| Interrupts | INTR, NMI, INTA̅ | maskable request, non-maskable request, acknowledge |
| Bus sharing | HOLD, HLDA | another master (e.g. [DMA](../registers-memory/io-techniques.html#3-direct-memory-access-dma)) asks for the bus |
| Timing | CLK, READY, RESET | clock, wait-state request, reset |
| Power | VCC (40), GND (1, 20) | +5 V supply |

## Multiplexed address and data

To save pins, **AD15–AD0** carry the address at the start of a bus cycle and data afterward.

1. **T1:** the 8086 puts the address on AD15–AD0 and A19–A16 and pulses **ALE** (address latch enable).
2. External latches (e.g. **8282**/74LS373) capture the address on ALE’s falling edge and hold it.
3. **T2–T4:** the same pins now carry data; **DEN̅** and **DT/R̅** control the data transceivers (8286).

This is the same idea as the 8085’s AD7–AD0 with ALE, extended to 16 bits.

## Minimum mode vs maximum mode

Pin 33 **MN/MX̅** chooses how the control signals are produced:

| | Minimum mode (MN/MX̅ = 1) | Maximum mode (MN/MX̅ = 0) |
|---|---|---|
| System | single processor, small | multiprocessor (e.g. with an 8087 coprocessor) |
| Control signals | generated by the 8086 itself (ALE, DEN̅, DT/R̅, M/IO̅, WR̅, INTA̅) | generated by an **8288 bus controller** from status lines S̅2 S̅1 S̅0 |
| Pins 24–31 mean | INTA̅, ALE, DEN̅, DT/R̅, M/IO̅, WR̅, HLDA, HOLD | QS1, QS0, S̅0, S̅1, S̅2, LOCK̅, RQ̅/GT̅1, RQ̅/GT̅0 |
| Bus sharing | HOLD / HLDA | RQ̅/GT̅ (request/grant) |

In maximum mode, **QS1/QS0** report the state of the instruction queue (so a coprocessor can follow along),
and **LOCK̅** keeps other processors off the bus during an instruction prefixed with `LOCK`.
